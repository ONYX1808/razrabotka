Вопросы:
1. Как работает связь между экранами Categories → Places → Details? Опишите
процесс передачи данных через навигацию.
2. Как реализована адаптивность для планшетов. Какие ещё подходы к
адаптивному дизайну вы могли бы использовать?
3. Как реализован однонаправленный поток данных в приложении? Приведите

Ответы:
1. Связь между экранами Categories → Places → Details реализована через навигацию с передачей параметров:  
На экране Categories используется компонент Link из expo-router для передачи выбранной категории через параметр category в URL (/places/[category]).  
На экране Places фильтруются места по категории, используя параметр category из useLocalSearchParams. Для каждого места создаётся ссылка с параметром id (/places/details/[id]).  
На экране Details параметр id используется для поиска соответствующего места в state.places из контекста PlacesContext, после чего отображается информация о месте.

2. Адаптивность для планшетов реализована с использованием useWindowDimensions в компоненте PlaceItem. Ширина экрана определяет, является ли устройство планшетом (isTablet), и на основе этого изменяется отображение, например, размеры изображений.  
Другие подходы к адаптивному дизайну:  
Использование библиотеки react-native-responsive-dimensions для расчёта размеров в процентах.  
Применение react-native-media-query для создания медиа-запросов.  
Разделение макетов для разных устройств с помощью платформенных файлов (.ios.tsx, .android.tsx).  

3. Однонаправленный поток данных реализован через контекст PlacesContext:  
Данные (places, categories) хранятся в состоянии контекста и передаются через провайдер PlacesProvider в _layout.tsx.  
Пример:  
В CategoriesScreen данные категорий берутся из state.categories.  
В PlacesScreen фильтруются места по категории, переданной через параметры.  
В DetailsScreen данные о месте извлекаются из state.places по id.  
Это обеспечивает однонаправленный поток: данные идут из контекста → компоненты → интерфейс.
