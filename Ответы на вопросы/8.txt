Вопросы:
1. Что такое HTTP?
2. Какие методы существует в HTTP?
3. Каким образом реализовано взаимодействие с Rick And Morty API?
Использовали ли вы инструменты и библиотеки для работы с сетью?
4. Как вы обрабатываете ошибки при запросах к API?
5. Какие компоненты вы использовали для отображения данных?
6. Как вы реализовали взаимодействие пользователя с элементами UI
(например, клики на карточки)?
7. Как работает переход на детальный экран при клике на элемент? Какие
данные вы передаете на детальный экран?

Ответы:
1. HTTP (HyperText Transfer Protocol) — это протокол передачи данных, используемый для обмена информацией между клиентом и сервером в сети Интернет.  

2. Основные методы HTTP:  
GET: Получение данных с сервера.  
POST: Отправка данных на сервер.  
PUT: Обновление данных на сервере.  
DELETE: Удаление данных на сервере.  

3. Взаимодействие с Rick And Morty API реализовано с использованием встроенного метода fetch. Для каждого типа данных (персонажи, локации, эпизоды) созданы функции (fetchCharacters, fetchLocations, fetchEpisodes) в файле api.tsx.  

4. Ошибки при запросах к API обрабатываются с помощью конструкции try-catch. Если запрос не удался, выбрасывается ошибка, которая затем отображается в интерфейсе через состояние error.  

5. Для отображения данных использовались компоненты:  
FlatList для списков.  
Text для текста.  
Image для изображений.  
TouchableOpacity для интерактивных элементов.  

6. Взаимодействие пользователя с элементами UI реализовано через компоненты TouchableOpacity и Link из expo-router. При клике на карточку вызывается переход на детальный экран.  

7. Переход на детальный экран работает через передачу параметров в URL. Например, при клике на карточку персонажа передаётся его id в параметрах (/details/character-details/[id]). На детальном экране данные извлекаются из API или контекста на основе переданного id.
